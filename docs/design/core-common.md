# Core 与 Common 模块设计

在Java开发中，特别是在使用大型框架或者构建大型应用程序时，经常会遇到`core`和`common`这两个术语。尽管这些术语在不同的项目中可能会有不同的具体含义，但它们通常代表了两种不同类型的模块或组件，旨在帮助开发者组织代码，提高代码的复用性和维护性。

---

## Common模块

Common模块通常包含那些可以被多个不同的模块或服务共享的代码和资源。这些资源可以是工具类、工具方法、配置类、通用接口定义等。Common模块的主要目的是为了减少代码的重复，提高代码的复用性。

**常见内容包括：**

- **工具类**：如日期处理、加密解密、文件操作等。
- **通用接口**：定义一些可以被多个服务或模块使用的接口。
- **配置类**：存放一些通用的配置，如数据库连接配置、API密钥等。
- **异常处理**：通用异常类和异常处理逻辑。

---

## Core模块

Core模块通常包含应用程序的核心业务逻辑和主要的组件。它是应用程序的核心所在，包含了实现主要功能的关键代码。Core模块主要负责处理应用程序的核心业务流程和关键功能。

**常见内容包括：**

- **业务逻辑**：如订单处理、用户管理等。
- **服务层**：定义了应用程序的核心服务接口及其实现。
- **实体类**：定义了应用程序中的核心实体（如用户、产品等）。
- **数据访问对象（DAO）**：处理与数据库的交互，但不直接包含具体的数据库访问代码，这部分可能会放在单独的Data或Repository模块中。

---

## 区别总结

| 维度       | Common模块                         | Core模块                         |
| ---------- | ---------------------------------- | -------------------------------- |
| 功能范围   | 通用功能和可复用组件               | 应用程序的核心业务逻辑和功能     |
| 依赖关系   | 通常不依赖Core模块                 | 可能依赖Common模块               |
| 独立性     | 独立性较高，可被多个项目共享       | 独立性较低，依赖具体应用结构     |

---

## 最佳实践

- **分离关注点**：通过将代码分为Common和Core模块，可以更好地分离关注点，使代码更加清晰和易于管理。
- **提高复用性**：通过在Common模块中封装通用功能和组件，可以增加代码的复用性，减少重复代码。
- **维护和扩展**：这样的模块化设计有助于在维护和扩展应用程序时更加高效。例如，当需要添加新功能或修改现有功能时，可以专注于Core模块的实现，而不必担心影响到其他部分的代码。

---

## 总结

理解和正确使用Common和Core这两个概念对于构建结构清晰、易于维护和扩展的Java应用程序至关重要。
