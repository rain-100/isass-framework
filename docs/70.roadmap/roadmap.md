# V4 路线图

只保留当前状态与后续工作，不重复实现细节。

## 已落地

- 模块命名、Java 25 / Spring Boot 4 升级、纯 Java 公共层与显式自动配置。
- IEntrypoint 入口目录、本地/HTTP 调用、统一 NoCode CRUD、事务与生命周期。
- Criteria 条件、游标与树查询、关联查询/写入和方向性级联删除；ORM 无关 Page。
- Java 模型和关系声明、生成器校验与类型化关系元数据。
- 数据授权 SPI、SQL 范围叠加、字段输入校验、隐藏字段序列化及授权写锁。
- 统一 JSON/异常、运行时 OpenAPI、文件流、Liquibase 和标准部署装配。
- docs 清理与模块 README 化；日志和路线图各限制 2000 字符。

## 近期验证与完善

- 在真实 MySQL/达梦及单体、微服务模式下验证关联 CRUD、事务回滚、租户隔离和数据授权；隔离测试通过不等于生产验收。
- 验证 MPJ 关联分页在大数据量、复杂关联下的性能与索引策略。
- 完善受保护条件批量写入、REPLACE/WRITE_NULL 等形态的安全授权；未实现前明确拒绝。
- 数据策略跨成员实体反向约束：评估自动 EXISTS 转换及关系歧义处理，不把同对象成员当成自动互相过滤。
- 聚合查询授权：规划 SUM/GROUP BY 等能力，防止借隐藏/脱敏字段推断原值；现有 count/exists 继续复用范围。
- 业务侧补齐权限变更/访问历史审计、真实数据库迁移及前后端联调；当前授权总览只解释当前授权。

## 后续评估

- 多 ORM 适配与数据库方言补齐，包括 SQL Server 授权写锁。
- TOML 配置方案及旧格式兼容；未定稿前继续现有配置。
- Docker 分层、GraalVM、CTE 树查询、动态 gRPC Server；均不作为当前已完成能力。
- 框架稳定后重新评估完整设计/使用文档与文档站。

## 边界

- 不重新引入 v1/v2/v3 并行 NoCode 或从 DDL 注释生成业务关系的旧路线。
- 框架只提供机制；业务数据对象、角色授权、默认方案与审计策略由业务模块管理。
- 每项落地同时提交实现、有效测试及简短日志，避免逐方法、逐重命名累积文档。
