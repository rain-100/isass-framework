# Agent 规则归属与文档维护

## 目标

共享框架规则只在 `isass-framework-v4` 维护一份。各工作区和业务微服务的 `AGENTS.md` 只保留执行任务前必须立即看到的摘要、项目边界和框架文档入口，不再复制完整的使用说明。

这样做有两个目的：

- 框架升级时，只修改框架 `AGENTS.md` 和对应的 `docs/usage/` 文档；
- 业务微服务只维护自己的领域规则、路径、运行方式和例外，避免多份规则逐渐不一致。

## 规则放置位置

| 内容 | 权威位置 | `AGENTS.md` 中的处理 |
| --- | --- | --- |
| Entrypoint、NoCode、数据库、Liquibase、生成器、关联、生命周期、初始化数据、内部认证 | 框架 `docs/usage/<topic>/` | 只写不可忽略的摘要并链接文档 |
| 框架仓库的构建、ChangeLog、模块边界和文档维护要求 | 框架 `AGENTS.md` | 保留摘要 |
| 工作区项目导航、CodeGraph 索引范围、跨项目协作入口 | 工作区根 `AGENTS.md` | 保留 |
| 微服务名称、模块、限界上下文、DDL 路径、生成器类、启动方式 | 微服务 `AGENTS.md` | 保留 |
| 具体领域术语、业务不变量、服务专有初始化器、缓存 key 和外部系统约束 | 微服务 `AGENTS.md` 或该服务文档 | 保留 |
| 完整示例、参数规则、边界条件和故障处理 | 对应 `docs/usage/` 文档 | 不复制到 `AGENTS.md` |
| 尚未确认的方案和阶段性讨论 | 设计文档或任务记录 | 不写入稳定使用规则 |

## 判断方法

满足以下任一条件的内容属于框架规则：

1. 两个或更多微服务必须采用相同实现；
2. 规则由框架接口、注解、生成器、运行时或 Starter 强制执行；
3. 变更会同时影响所有业务服务的调用方式或生成结果；
4. 内容解释的是通用事务、序列化、路由、安全、数据库或测试机制。

满足以下任一条件的内容属于业务服务规则：

1. 只描述一个服务的业务含义、状态机或领域不变量；
2. 包含该服务独有的目录、类名、端口、配置项、权限或外部系统；
3. 是框架通用规则在该服务中的明确选择或受控例外。

若业务服务确需偏离框架规则，必须在自身 `AGENTS.md` 写明偏离项、原因和适用范围；不能复制并修改一份框架规则来形成隐式分叉。

## 修改流程

修改共享机制时按以下顺序处理：

1. 修改框架实现、生成器或模板；
2. 更新对应的框架 `docs/usage/`；
3. 仅在执行摘要发生变化时更新框架 `AGENTS.md`；
4. 检查业务微服务是否存在真正的服务专有适配；
5. 不同步复制规则正文到业务微服务 `AGENTS.md`。

创建新微服务时，其 `AGENTS.md` 应直接引用框架文档，并只补充该服务的专有信息。
